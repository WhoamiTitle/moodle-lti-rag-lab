Локальные проверки: 10 октября 2026. Node.js 24.10.0; `ltijs 7.0.7`, Express 5.2.1.

Ниже разделены автоматические тесты с имитационной платформой, браузерная проверка настоящего локального Moodle 5.3 и последующий проход настоящего Gnomio через Helios. ## Сверка API со стартером

Источник контракта — `Moodle_LTI_Three_Tasks_Starter.zip` от 07.10.2026, в частности `src/tool.mjs` и `public/app.js`. До исправления семь новых HTTP-тестов были запущены на прежнем коде: все семь завершились ожидаемыми ошибками. Воспроизведены отсутствие полей сессии стартера, плоский результат submit, 202 вместо 502, ответ `{current: null}` вместо `{ok: true}`, принятие POST без Origin, машинный код вместо читаемой error и обрезка/порядок истории. После исправления все семь проходят.

HTTP-проверки используют подписанные синтетические LTI-запуски и реальный локальный HTTP-сервер приложения, но сервис Moodle и LTI-хранилище остаются имитационными. Дополнительные шесть тестов исполняют настоящий браузерный модуль `public/api.js` с управляемыми ответами fetch; это проверка клиентского преобразования, не отдельное доказательство браузерного рендеринга или реального Moodle.

Подтверждённый повтор возвращает `duplicate: true` без нового AGS, включая архивный UUID; неподтверждённый повтор сохраняет UUID и ответы, а при подтверждении переходит в `sent`. Отказ из-за Origin проверен на обоих POST с действительными CSRF и сессией, в том числе при `Sec-Fetch-Site: same-origin` без Origin. Отклонённые запросы не сохраняют/архивируют попытку и не вызывают AGS.

Обязательные поля стартера восстановлены, дополнительные метаданные интерфейса описаны в README. API выдаёт полную историю хронологически; ограничение в 20 строк применяется только браузером. DTO выводится из существующей схемы версии 1: новые публичные поля не записываются в JSON, адрес колонки AGS остаётся приватным.

## Настоящий Moodle 5.3: два студента и AGS

10.10.2026 на Mac ARM64 использованы Moodle 5.3 / PHP 8.3.35 / PostgreSQL 17.11, MongoDB 8.0.32 и обычный `src/server.mjs` с `.env.lti-local`. `MemoryLtiDatabase`, mock platform и `make demo` не подключались. ## Итоговые локальные оценки и живые отказы API

Затем студент Б выполнил обычную новую попытку в браузере: `RAG / неверно / API` → 7/10. В настоящем журнале оставлены **А = 10, Б = 7**, исходная колонка одна. В `grade_grades_history` у Б добавлена только запись ID 15 через `modltiservice_gradebookservices`; А не изменился.

Отдельный `lti_instructor` получил только курсную роль `teacher`, без прав администратора сайта. Подписанный запуск Moodle содержит настоящий `membership#Instructor`; приложение показывает `learner: false`, пустую историю и заблокированную отправку.

`make lti-local-verify` прошёл девять отрицательных HTTP-сценариев через реальные Moodle/OIDC/LTI-сессии и MongoDB: подмена `userId`/`scoreGiven` и отсутствие `q3` → 400; отсутствие/неверный CSRF, отсутствие/чужой Origin и оба POST Instructor → 403. После каждого отказа отдельным чтением проверены неизменность оценок, всей истории Moodle и SHA-256 файлов попыток. У преподавателя нет строки оценки, истории оценки и файла попыток. Повтор подготовки преподавателя и повтор живого протокола также прошли, сохранив А = 10 / Б = 7.

[Итоговый протокол](local-lti-final-checks.md) разделяет реальные браузерные снимки, протокольные HTTP-ответы и автоматические тесты. ## Настоящий Gnomio через публичный HTTPS Helios

11.10.2026 в `eoweblab.gnomio.com` сохранён LTI 1.3 инструмент «RAG-тренажёр · Helios · LTI 1.3»:
JWKS, новое окно, только AGS grade sync, Never для имени и почты, без roster/Deep Linking/Tool Settings.
В приватную конфигурацию Helios внесены реальные публичные реквизиты регистрации; после перезапуска
`/healthz` — `configured:true`, JWKS инструмента содержит один RSA-ключ. Тестовые адаптеры не включались.

В курсе Test (ID 2) создан отдельный элемент LTI, course-module ID 6, числовой максимум 10.
Существующие SCORM и их оценки не изменялись. Администратор с курсной ролью Teacher запустил
инструмент только для просмотра: поля и отправка отключены. Это не отдельная учётная запись Instructor.

Для уже существующего вымышленного `student1` (ID 3) использована штатная функция Moodle «Войти как»;
