# Проверка текущей реализации

Дата: 10 октября 2026. Node.js 24.10.0; `ltijs 7.0.7`, Express 5.2.1.

Это **локальные** результаты, не подтверждение совместимости зарегистрированного Gnomio-инструмента. На внешней границе заменены Moodle и хранилище LTI библиотеки. Настоящие: `ltijs`, RSA-подписи, OIDC recovery/state/nonce, JWT client assertion, HTTP OAuth и AGS. Хранилище попыток — реальный файловый каталог.

## Автоматические проверки

Команда: `npm test`.

Финальный прогон: **23 теста, 23 пройдено**. Чистая установка `npm ci` воспроизведена; npm сообщил 0 известных уязвимостей. Синтаксис JS/MJS проверен `node --check`; `docker compose config --quiet` подтвердил структуру compose-файла (не запуск БД).

## Браузер

Встроенный браузер прошёл login → test platform form_post → state recovery → session → `/app`. Проверены заполнение, 7/10, «Новая попытка», 10/10 при AGS 503 (`pending`), замороженные ответы и успешный повтор до `sent` с двумя запросами доставки. Участники вымышленные, без личных данных.

После перезапуска проверены восстановленная история, новая успешная попытка 10/10 и режим преподавателя с заблокированной отправкой. На узком экране горизонтальное переполнение отсутствовало: `clientWidth = scrollWidth = 375`. Ошибок/предупреждений браузера в финальной проверке не было.

## Что ещё не проверено

- Регистрация, запуск и журнал **реального** Moodle/Gnomio.
- Production MongoDB adapter, сохранение ключей в реальной БД и резервное восстановление MongoDB.
- Reverse proxy/TLS на публичном домене, масштаб оценки и overrides конкретного курса.
- Старый Moodle с PEM вместо JWKS.
- Нагрузочная устойчивость и эксплуатационный аудит безопасности.

Для завершения лабораторной пройти [проверку подключения](moodle-setup.md#5-проверить-реальную-передачу), добавить фактические снимки журнала Moodle и таблицу ожидаемых/полученных оценок. Не подменять их снимками тестового журнала.
