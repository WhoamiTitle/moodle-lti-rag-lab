## Требования

- Node.js 24+; проверенная версия — 24.10.0. Зависимости закреплены в `package-lock.json`.
- Bash, Make и Docker Desktop с Compose. Для `make test`/`make demo` Docker не нужен; для полного `make check-ci` нужен, поскольку shell/PHP-проверки выполняются в закреплённых образах.
- Доступ в интернет при первой установке зависимостей и загрузке Docker-образов. После сборки тестовый контейнер работает без сети.

## Команды

Все команды вызываются из корня репозитория. Shell-хелперы также можно запускать из другого каталога: пути окружений и Compose они вычисляют самостоятельно.

```sh
make install
make check-ci
make test-docker
```

| Команда                                 | Назначение                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------ |
| `make install`                          | `npm ci`, установка по lockfile                                                |
| `make lint`                             | ESLint, ShellCheck, `bash -n`, `php -l`                                        |
| `make format-check`                     | Неизменяющая проверка Prettier и shfmt                                         |
| `make format`                           | Явные автоисправления ESLint, Prettier и shfmt; после команды просмотрите diff |
| `make test`                             | Все Node.js-тесты, включая безопасность LTI и shell-автоматизацию              |
| `make coverage`                         | Отчёт встроенного Node.js coverage для `src/`                                  |
| `make check` / `make check-ci` / `make` | Lint + проверка формата + тесты, без изменения исходников                      |
| `make test-docker`                      | Сборка и запуск той же тестовой программы в изолированном Linux-контейнере     |
| `make npm-audit`                        | Явная проверка известных уязвимостей npm; ошибки не подавляются                |
| `make demo`                             | Синтетическая LTI-платформа и тренажёр на loopback                             |
| `make help`                             | Краткая справка                                                                |

`make check-ci` не вызывает автоисправления. `npm run lint:fix` и `npm run format` доступны отдельно, но не подменяют проверку shell/PHP и тестов. CI запускает `make check-ci`, затем `make test-docker`; отправка изменений в GitHub выполняется только по отдельному запросу.

## Код-стайл

- JavaScript/HTML/CSS: отступ 2 пробела, двойные кавычки, точки с запятой, LF, финальная новая строка; целевая длина строки 120. Формат задаёт `.prettierrc.json`, базовые настройки редактора — `.editorconfig`.
- ESLint: рекомендованные проверки ошибок, строгие сравнения, обязательные фигурные скобки, отсутствие `eval`/`var`, неиспользуемых переменных; сортировка имён внутри импорта без перестановки самих импортов.
- Имена отражают назначение. Снимок попыток называется `snapshot`, не абстрактным `state`. Протокольное OIDC-поле `state`, методы `Map.get()` и другие внешние контракты не переименовываются.
- Shell: Bash, строгий режим, отступ 2 пробела, кавычки вокруг подстановок, остановка при ошибке. shfmt форматирует, ShellCheck проверяет; версии образов закреплены digest в `shell_checks.sh`.
- PHP: отступ 4 пробела и проверка синтаксиса тем же базовым PHP-образом, что используется для Moodle. Это не полноценный PHP static analyzer.
- Существующие модули разделены по ответственности. Новый слой вводится при реальной необходимости, а не ради копирования дерева Python-референса.

## Окружения и сервисы

```sh
make local-env
make mongo-up
make start
```

`make local-env` создаёт `.env` из `.env.example`, не заполняя реквизиты Moodle за пользователя. `make mongo-up` управляет только MongoDB из `compose.yaml` проекта `moodle-lti-rag-lab`; `make mongo-down` останавливает этот Compose project без удаления тома. Если порт 27017 занят, сначала выберите другой порт/`MONGO_URL` или используйте существующую разрешённую БД.

Для отдельной настоящей LMS:

```sh
make moodle-env
make moodle-init
make moodle-status
```

`moodle-env` создаёт только конфигурацию: отдельные криптографически случайные пароли БД и администратора через `node:crypto`, права `600`. `moodle-init` также собирает/запускает сервисы, выполняет идемпотентную CLI-установку от `www-data`, очищает кэш и ждёт healthcheck. Существующие конфигурация, база и тома не сбрасываются. Подробности — в [local-moodle.md](local-moodle.md).

Для настоящего локального LTI после установки LMS: `make lti-local-init`, `make lti-local-start`, затем в другом терминале `make lti-local-activate`. `make lti-local-status` читает фактические оценки Moodle. Shell-оркестрация — в `scripts/makefile/lti_local.sh`; приватные env и обмен CLI — в `scripts/local-lti.mjs`; создание курса/студентов/регистрации штатными Moodle API — в `docker/moodle/lti-lab.php`. Помощник не записывает учебные оценки. Контракт HTTP приложения не менялся. Подробности и реальные доказательства — в [local-lti.md](local-lti.md).

Не публикуйте обычный `docker compose config` или содержимое `.env`: они могут раскрыть секреты. Для проверки структуры Compose используйте `./scripts/moodle.sh config --quiet`. Команды `moodle-down`/`mongo-down` не добавляют `-v`.

## Тестовая изоляция и границы доказательств

- Тесты оценивания, файловых попыток и сессий проверяют настоящие модули приложения.
- LTI/AGS-тесты используют настоящий `ltijs` и HTTP, но синтетическую платформу и тестовый адаптер хранилища. Они не доказывают интеграцию с реальным Moodle/Gnomio.
- `test/tooling.test.mjs` создаёт временные каталоги и fake Docker executable. Проверяет права/env, отсутствие перезаписи, порядок команд, отказ при ошибке и отсутствие опасных дополнительных флагов.
- `test-docker` запускает контейнер от непривилегированного `node`, с `--network none`, read-only root и временным `/tmp`. Для выполнения shell-фикстур у `/tmp` явно задан `exec`; `nosuid`/`nodev` сохранены. Нет портов, host data mounts, MongoDB и Moodle. Секреты и учебные данные исключены из build context через `.dockerignore`.
- Ручной smoke-test настоящего Moodle документируется отдельно. GitHub CI и локальные hooks считаются выполненными только после реального запуска.
- Coverage — диагностический отчёт по загруженным тестами модулям `src/`, не универсальная мера безопасности. CLI entrypoint `src/server.mjs` в него не входит, поскольку тесты запускают `createTool` напрямую. Измеренный результат и непроверенные сценарии — в [verification.md](verification.md).

## Необязательные Git hooks

Конфигурация добавлена, но hooks автоматически не устанавливаются. Если `prek` или `pre-commit` уже установлен и вы хотите включить проверки перед коммитом:

```sh
prek install
prek run --all-files
```

Эквивалентные команды для `pre-commit`: `pre-commit install` и `pre-commit run --all-files`. Локальный hook вызывает `make check`; остальные проверяют формат файлов, конфликтные маркеры, shebang/исполняемость и утечки приватных ключей. Для полного hook-прогона нужен Docker. Проверки ключей не заменяют внимательный просмотр diff и `.gitignore`.

Первичная документация инструментов: [ESLint flat config](https://eslint.org/docs/latest/use/configure/configuration-files), [Prettier configuration](https://prettier.io/docs/configuration), [shfmt](https://github.com/mvdan/sh).
