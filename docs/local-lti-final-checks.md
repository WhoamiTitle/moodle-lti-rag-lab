# Итоговые локальные проверки Moodle LTI

10 октября 2026 на настоящем локальном Moodle 5.3 подтверждены разные оценки двух студентов: **А — 10/10, Б — 7/10**, одна колонка LTI с максимумом 10. Настоящий Instructor имеет только доступ к просмотру. Все девять отрицательных HTTP-проверок вернули ожидаемые 400/403, не изменив оценки, историю Moodle или файлы попыток.

## Оценки студентов

| Участник  | Учётная запись             | Текущая оценка | История оценок Moodle |
| --------- | -------------------------- | -------------- | --------------------- |
| Студент А | `lti_student_a`, user ID 3 | 10/10          | 0 → 7 → 10            |
| Студент Б | `lti_student_b`, user ID 4 | 7/10           | 0 → 7 → 10 → 7        |

Для Б создана новая обычная попытка в браузере с ответами `RAG / неверно / API`; отправка выполнена клавишей Enter. Сервер рассчитал 7, Moodle принял оценку через AGS. В истории появилась запись ID 15 с источником `modltiservice_gradebookservices`. Оценка и история А не изменились. Ручная правка журнала и overrides не использовались.

Сохранён исходный grade item ID 2: дополнительных колонок LTI нет. Course ID и course-module ID — 2, resource link ID — 1. [Настоящий журнал Moodle](http://localhost:8000/grade/report/grader/index.php?id=2) показывает 10,00 и 7,00. В новом клоне ID могут отличаться; ссылки выдаёт `make lti-local-status`.

## Роль Instructor

Проверка выполнена отдельной учётной записью `lti_instructor` (user ID 5), не переключением роли администратора. В контексте учебного курса назначена только роль `teacher` — преподаватель без права редактирования; прав администратора сайта нет.

Moodle выдал подписанный LTI-запуск с ролью `http://purl.imsglobal.org/vocab/lis/v2/membership#Instructor`. Сессия приложения содержит `learner: false`, `current: null` и пустую историю. В браузере поля и отправка заблокированы, кнопки новой попытки нет. Прямые POST к обоим маршрутам также отклонены с 403 `read_only`.

У преподавателя отсутствуют строка оценки и записи истории оценок Moodle. Файла его попыток нет: в каталоге остаются только два JSON-файла студентов.

## Отказы API на настоящем стенде

| Запрос                                        | Участник   | Получено | Код                      |
| --------------------------------------------- | ---------- | -------- | ------------------------ |
| Лишнее поле `userId` с ID другого студента    | Б          | 400      | `invalid_body`           |
| Лишнее поле `scoreGiven` с готовыми баллами   | Б          | 400      | `invalid_body`           |
| В `answers` отсутствует `q3`                  | Б          | 400      | `AnswersValidationError` |
| Нет заголовка CSRF                            | Б          | 403      | `invalid_csrf`           |
| Неверный заголовок CSRF                       | Б          | 403      | `invalid_csrf`           |
| Нет Origin                                    | Б          | 403      | `cross_origin`           |
| Чужой Origin                                  | Б          | 403      | `cross_origin`           |
| Instructor отправляет `POST /api/submit`      | Instructor | 403      | `read_only`              |
| Instructor отправляет `POST /api/new-attempt` | Instructor | 403      | `read_only`              |

Остальные реквизиты каждого запроса действительны, чтобы проверять именно указанный запрет. Учётные записи входят в настоящий Moodle; сервер получает его подписанные OIDC/LTI-запуски и проверяет их обычным `ltijs` с реальной MongoDB. Это протокольный HTTP-клиент, не имитация Moodle, не поддельные JWT и не запись браузерного DevTools.

После **каждого** отказа отдельно прочитаны `grade_grades` и `grade_grades_history` штатным CLI Moodle от `www-data`, включая отсутствие оценок Instructor. Сравнены SHA-256 и состав файлов попыток. Итоговые оценки, история и файлы совпали с исходными; число колонок LTI осталось равным одному.

Полные HTTP-статусы, коды, сообщения и снимки данных до/после сохранены в [JSON-протоколе](local-lti-negative-evidence.json). [HTML-протокол](local-lti-negative-report.html) — наглядное представление именно этих результатов; его снимок не является снимком сетевой панели браузера.

## Повторение проверок

Нужны запущенные локальные Moodle, PostgreSQL, MongoDB и `make lti-local-start` в отдельном терминале. Подготовка и активация описаны в [инструкции локального LTI](local-lti.md).

```sh
make lti-local-instructor
make lti-local-status
make lti-local-verify
make check-ci
make test-docker
```

`lti-local-instructor` создаёт только синтетического преподавателя этого учебного курса через Moodle API. Пароль находится в приватном, исключённом из Git `.env.lti-instructor` с правами 600. Повторная команда сохраняет пароль и существующую учётную запись; чужой аккаунт или небезопасный файл не перезаписывает.

`lti-local-verify` требует исходные А = 10 и Б = 7. Если значения другие, команда останавливается **до отправки тестовых POST**, не исправляя оценки. Она отправляет только отрицательные запросы, не выполняет разрешённую отправку Learner или новую попытку. Не меняйте ожидаемые значения ради зелёного результата: нужную оценку получают обычным прохождением тренажёра.

HTTP-клиент принимает только `http://localhost:8000` и `http://localhost:3000`, включая перенаправления. Пароли, cookies, JWT, CSRF и recovery tokens в отчёт не выводятся. Значение чужого Origin — только тестовый заголовок; сетевого обращения к чужому адресу нет.

`make check-ci` успешно проверил ESLint, Prettier, ShellCheck, shfmt, Bash/PHP и **59/59 тестов** на macOS. `make test-docker` также прошёл **59/59** в изолированном Linux ARM64-контейнере, без сети, портов и реальных томов. Пять новых тестов проверяют приватность и сохранение реквизитов Instructor, разбор протокольных форм и ограничения URL. Эти автоматические тесты отдельно от девяти живых HTTP-проверок.
