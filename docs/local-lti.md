# Настоящий LTI 1.3: локальный Moodle и RAG-тренажёр

Проверено 10.10.2026: два отдельных студента прошли **0 → 7 → 10**, все шесть результатов приняты настоящим Moodle через AGS. После дополнительной попытки Б оставлены **А = 10, Б = 7**; отдельный Instructor и девять живых проверок 400/403 пройдены. [Итоговый протокол и снимки](local-lti-final-checks.md). Это не `make demo` и не тестовый журнал. Всё работает только на Mac: Moodle `http://localhost:8000`, тренажёр `http://localhost:3000`, MongoDB на `127.0.0.1:27017`. Gnomio и Cloudflare не используются.

## Запуск

Нужны Node.js 24+, Make, Bash и работающий Docker Desktop. Если Moodle ещё не установлен, сначала выполните `make install` и `make moodle-init` по [инструкции LMS](local-moodle.md). Для существующего стенда:

```sh
make lti-local-init
make lti-local-start
```

`lti-local-start` занимает терминал; остановка — `Ctrl+C`. В другом терминале:

```sh
make lti-local-activate
make lti-local-status
```

`init` собирает Moodle с CLI-хелпером, ждёт настоящие Moodle/PostgreSQL/MongoDB, создаёт только учебный курс, две учётные записи и один External tool. Конфигурация получается из `get_tool_type_config()` самого Moodle, а не из выдуманных client/deployment ID. Новая регистрация остаётся pending, пока не добавлен настоящий публичный RSA-ключ запущенного тренажёра. Приватный ключ остаётся в MongoDB.

`activate` добавляет открытый ключ и включает регистрацию. Повтор с тем же ключом разрешён; несовпадающий ключ не заменяется автоматически. `status` только читает регистрацию, текущие оценки и историю Moodle, ничего не оценивает и не отправляет.

Повторная подготовка сохраняет курс, студентов, client ID, колонку, пароли и оценки. Существующий чужой аккаунт/регистрация, небезопасный файл или другой пароль вызывают отказ, а не перезапись. Никакие тома не удаляются. `.env` обычного сервера и `data/demo` не используются для этого подключения.

Стенд этого помощника намеренно закреплён на `localhost:8000/3000`. Изменение портов/origin требует согласования регистрации и конфигурации, а не подмены адреса только в браузере.

## Вход и проверка

- Курс: [RAG-LTI-LAB](http://localhost:8000/course/view.php?id=2).
- Элемент: [Тренажёр RAG · 3 задания / 10 баллов](http://localhost:8000/mod/lti/view.php?id=2).
- Администратор: логин и пароль в локальном `.env.moodle`; [журнал оценок](http://localhost:8000/grade/report/grader/index.php?id=2).
- Студенты: `lti_student_a`, `lti_student_b`; отдельные случайные пароли находятся в `.env.lti-students`.
- Instructor: `lti_instructor`, отдельный пароль в `.env.lti-instructor`; создаётся командой `make lti-local-instructor`, только роль `teacher` в этом курсе, без прав администратора сайта.
- Сервер: `.env.lti-local`, попытки — `data/local-lti-attempts/`. Эти файлы исключены из Git; env имеют права `600`, каталог попыток — `700`.

В новом клоне числовые ID могут отличаться: берите ссылки из `make lti-local-status`. Здесь course ID = 2, course-module ID = 2, **LTI resource link ID = 1**, grade item ID = 2. ID ресурса — ID экземпляра LTI, а не ID модуля в URL.

Войдите именно отдельным студентом, не используйте переключение роли администратора. Откройте элемент через курс; интерфейс появляется в новом окне. Для следующего результата нажмите «Новая попытка»:

| Ответы q1 / q2 / q3   | Ожидается | Проверено у A | Проверено у B |
| --------------------- | --------- | ------------- | ------------- |
| пусто / пусто / пусто | 0/10      | 0/10          | 0/10          |
| RAG / неверно / API   | 7/10      | 7/10          | 7/10          |
| RAG / embedding / API | 10/10     | 10/10         | 10/10         |

После B = 0 оценка A осталась 10. При первом запуске B его история была пустой, без попыток A. Первый проход закончился текущими 10 у обоих и собственной историей 0/7. Затем обычная новая попытка B с `RAG / неверно / API` дала 7: текущее состояние **A = 10, B = 7**, история B — 0/7/10. Все обновления идут в **одну** исходную колонку; Moodle хранит последнюю оценку. Обновление страниц не добавило записей AGS. Администратор и отдельный преподаватель открывают задания только для просмотра; их оценок нет.

Сверка выполнялась после каждого ответа независимым чтением Moodle: `grade_grades` и `grade_grades_history`, источник `modltiservice_gradebookservices`. Хелпер подготовки не вызывает API оценивания, не вставляет оценки и не меняет overrides. Ожидаемые и фактические значения сохранены в [машинном протоколе](local-lti-evidence.json).

Итоговые локальные проверки после этого прохода:

```sh
make lti-local-instructor
make lti-local-verify
```

`verify` требует А = 10 / Б = 7 и запущенный настоящий сервер. Проверяет подмену пользователя/баллов и структуру ответов (400), CSRF/Origin и оба POST Instructor (403). После каждого отказа сверяет реальные оценки, историю и SHA-256 файлов попыток, не выполняет разрешённую отправку Learner. ## Почему открытый PEM-ключ, а не URL ключей

Moodle 5.3 поддерживает в LTI 1.3 оба способа: `JWK_KEYSET` и `RSA_KEY`. На этом локальном стенде выбран `RSA_KEY`: Moodle проверяет JWT client assertion уже сохранённым открытым ключом и не должен скачивать его с `localhost:3000` **внутри контейнера**. Node.js на Mac получает JWKS Moodle, OAuth token и отправляет AGS по `localhost:8000`; браузер открывает оба origin на Mac.

Это остаётся LTI 1.3 / RS256 / AGS, не LTI 1.1 и не shared secret. Подпись, issuer, deployment, nonce, роль, Origin и CSRF не отключались. Глобальные `curlsecurityblockedhosts` и `curlsecurityallowedport` Moodle оставлены без изменений; HTTP-серверы привязаны к loopback, PostgreSQL наружу не опубликован.

HTTP допустим **только для этого синтетического loopback-стенда**. Требование лабораторной о HTTPS-развёртывании на домене этим этапом не закрыто. Для удалённого Moodle нужны HTTPS и доступный ему JWKS URL; следуйте [отдельной инструкции](moodle-setup.md). Не отключайте TLS и не открывайте БД наружу. После смены ключей в MongoDB PEM требует явной согласованной перерегистрации; автоматической ротации здесь нет.

Настройки Moodle сверены с [официальной документацией](https://docs.moodle.org/503/en/LTI_External_tools) и исходным кодом установленной Moodle 5.3 (`mod/lti/edit_form.php`, `locallib.php`, gradebookservices). Все учётные записи и email в доказательствах вымышленные.
