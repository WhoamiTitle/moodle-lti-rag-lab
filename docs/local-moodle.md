# Локальный Moodle с PostgreSQL в Docker

Отдельная настоящая LMS для ручных учебных тестов. Базовый `make moodle-init` поднимает только Moodle/PostgreSQL. Дополнительно подготовлено и проверено [локальное подключение LTI 1.3](local-lti.md) к обычному Node.js-тренажёру с MongoDB. Cloudflare и Gnomio не используются; `make demo` остаётся отдельной имитацией.

## Состав и границы

- Moodle **5.3**, официальный release-архив с проверкой SHA-256 при сборке.
- PHP 8.3 + Apache из `moodlehq/moodle-php-apache`; образ закреплён digest и поддерживает ARM64/AMD64.
- PostgreSQL 17; отдельная база `moodle`, образ закреплён digest.
- Только два контейнера: `moodle` и `postgres`. MongoDB, Selenium, SMTP, туннель и LTI-приложение не запускаются.
- Moodle доступен с Mac по **http://localhost:8000**. Порт привязан к `127.0.0.1`, PostgreSQL вообще не публикует порт на хосте.
- Отдельный Compose project: `moodle-rag-local`. Он не использует контейнеры и тома других проектов.
- Русский язык запрашивается при установке. Для скачивания образов, Moodle и языкового пакета при первом запуске нужен интернет.
- Apache обслуживает `public/`, открывает реальные страницы `index.php` и передаёт отсутствующие пути маршрутизатору Moodle. Настройка закреплена в `docker/moodle/fallback.conf`, а не сделана вручную внутри контейнера.
- Отправка почты отключена (`noemailever`); адрес администратора вымышленный. Не загружайте реальные персональные данные в учебный стенд.

Это конфигурация **только для локального HTTP**, не production-развёртывание. Локальный LTI использует согласованные loopback-адреса и открытый RSA PEM-ключ, без отключения подписи/роли или сетевых ограничений Moodle. Для удалённого подключения отдельно нужны HTTPS и сетевой доступ между LMS и инструментом.

## Первый запуск после клонирования

Нужны Node.js 24+, Bash, Make и запущенный Docker Desktop с Docker Compose. Перейдите в корень репозитория:

```sh
make moodle-init
make moodle-status
```

`moodle-init` создаёт `.env.moodle` с правами `600`, генерирует два разных пароля через `node:crypto`, собирает/запускает сервисы, выполняет установку Moodle от `www-data`, очищает кэш и ждёт healthcheck. Пароли не печатаются и не передаются в аргументах CLI-установщика. Существующий `.env.moodle` (в том числе symlink) не перезаписывается; установленная база и тома не сбрасываются.

Если сначала нужно изменить порт или название сайта:

```sh
make moodle-env
```

Откройте созданный `.env.moodle` в редакторе, внесите настройки, затем вызовите `make moodle-init`. Два сгенерированных поля:

- `MOODLE_LAB_DB_PASSWORD` — отдельный пароль PostgreSQL.
- `MOODLE_LAB_ADMIN_PASSWORD` — пароль администратора Moodle, не короче 12 символов с буквами разного регистра, цифрой и спецсимволом.

Если файл уже существовал с пустыми паролями, хелпер намеренно не исправляет его: заполните оба поля вручную перед запуском. Сохраните значения только в `.env.moodle`; не добавляйте их в примеры и отчёты.

Этот файл отделён от `.env` Node.js-приложения. `.env.moodle` исключён из Git; `.env.moodle.example` с пустыми паролями включён. Не используйте пароль аккаунта Gnomio.

```sh
./scripts/moodle.sh config --quiet
make moodle-up
make moodle-install
make moodle-status
```

Последний блок — раздельные шаги, если установка выполняется вручную; после `moodle-init` повторять их не обязательно. `scripts/makefile/moodle.sh` реализует Make-команды, а `scripts/moodle.sh` остаётся тонкой обёрткой над `docker compose --env-file .env.moodle -f compose.moodle.yaml` для дополнительных CLI-операций. Она всегда выбирает именно локальный Moodle, независимо от текущего каталога. **Не запускайте обычный `config` без `--quiet` в записи экрана:** Compose выводит раскрытые значения окружения.

Команда установки использует штатный CLI-установщик Moodle от имени `www-data`, создаёт администратора и схему. Пароль не попадает в аргументы процесса. Повтор на установленной базе не меняет данные или пароль администратора. При ошибке неполной установки скрипт останавливается, а не удаляет базу.

`make moodle-install` и `make moodle-init` очищают кэш после установки: healthcheck мог заполнить его ещё до завершения настройки языка. Все дополнительные CLI-команды Moodle, включая очистку кэша и cron, запускайте от имени `www-data`, чтобы не создавать недоступные веб-серверу файлы.

После успешной установки оба контейнера должны стать `healthy`. До инициализации базы Moodle может быть `starting`/`unhealthy`; сначала завершите CLI-установку и изучите её ошибки. При первой сборке нужно скачать архив Moodle и несколько слоёв PHP-образа.

## Вход в браузере

Откройте **http://localhost:8000/login/index.php**:

- логин — `MOODLE_LAB_ADMIN_USER`, по умолчанию **admin**;
- пароль — значение `MOODLE_LAB_ADMIN_PASSWORD` из локального `.env.moodle`.

На первом входе Moodle может предложить заполнить профиль/настройки сайта. Это отдельный локальный аккаунт; пользователи и курсы Gnomio сюда автоматически не переносятся.

Изменение `MOODLE_LAB_ADMIN_PASSWORD` после установки **не сбрасывает** пароль в базе. Смените его через профиль Moodle. Аналогично изменение PostgreSQL-пароля в окружении само по себе не изменяет пароль пользователя уже существующей базы.

Для будущих тестов можно создать курс, отдельного преподавателя и зачисленных учеников. LTI-регистрация и передача оценок в этом шаге не настраиваются.

## Остановка, запуск и сохранение данных

```sh
make moodle-stop
make moodle-start
```

Или перезапуск двух сервисов:

```sh
make moodle-restart
```

Данные расположены в именованных томах:

| Том                              | Что хранится                                            |
| -------------------------------- | ------------------------------------------------------- |
| `moodle-rag-local_postgres-data` | Пользователи, курсы, настройки и оценки PostgreSQL      |
| `moodle-rag-local_moodle-data`   | Загруженные файлы, языковые пакеты, кэш и сессии Moodle |

Остановка, перезапуск и пересоздание контейнеров с теми же томами сохраняют данные. `make moodle-down` убирает контейнеры и сеть только этого проекта, но не удаляет тома. Не используйте `down -v`, `docker volume rm` или очистку Docker с volumes: они могут удалить курсы и файлы. Эта инструкция не удаляет данные и не выполняет миграцию на другую версию Moodle.

## Cron и ограничения

Автоматический cron сейчас **не запущен**: стенд состоит только из Moodle и PostgreSQL. Для выполнения отложенных действий/резервных копий можно вызвать штатный cron вручную:

```sh
make moodle-cron
```

Для постоянного использования нужно отдельно настроить регулярный cron. Предупреждение Moodle о давно не выполнявшихся задачах не означает потерю данных.

## Проверки и диагностика

```sh
make moodle-status
make moodle-logs
curl --fail --silent --output /dev/null --write-out '%{http_code}\n' http://localhost:8000/login/index.php
curl --fail --silent http://localhost:8000/core/check/controller/test
```

Проверьте вход администратора, русский интерфейс, открытие Site administration и повторный вход после перезапуска. Работа базовой LMS сама по себе не доказывает LTI; фактические LTI-проверки этого стенда записаны [отдельно](local-lti.md). Они не являются доказательством работы Gnomio.

Тест маршрутизатора должен вернуть `Test controller response`. Один только флаг `routerconfigured` не доказывает работу Apache: проверяйте реальный HTTP-ответ.

Если порт 8000 занят, выберите свободный `MOODLE_LAB_PORT` и одновременно задайте соответствующий `MOODLE_LAB_URL=http://localhost:НОВЫЙ_ПОРТ`, затем выполните `make moodle-up`. Во всех ссылках используйте выбранный адрес, без переключения между `localhost` и `127.0.0.1`.

Не запускайте второй Compose project на существующих томах. Не подключайте PostgreSQL этого стенда к базе другого приложения.

## Результат локальной проверки — 10.10.2026

На Mac с Docker Desktop ARM64 проверено:

- Moodle 5.3 (Build: 20261005), PHP 8.3.35, PostgreSQL 17.11; оба контейнера `healthy`.
- Вход администратора с паролем из `.env.moodle`, личный кабинет `/my/` и `/admin/search.php` открываются; интерфейс русский.
- Реальный маршрут `/core/check/controller/test` возвращает HTTP 200 и ожидаемый ответ контроллера.
- Повторный запуск CLI-установщика завершается без изменений данных и пароля администратора.
- После перезапуска обоих контейнеров снова работает вход; версия, язык, запись администратора и число курсов в PostgreSQL не изменились. SHA-256 файла русского языкового пакета в томе `moodle-data` также совпал до и после перезапуска.
- После переноса Make/Bash-автоматизации `make moodle-init` повторно прошёл на существующем стенде: `.env.moodle`, администратор, язык, версия, число пользователей/курсов и русский языковой файл сохранились; оба контейнера стали `healthy`, вход и маршрутизатор работают.
- `make check-ci` и изолированный `make test-docker`: 32/32 теста (23 приложения + 9 автоматизации). Это отдельные тесты, а не проверка LTI с этим Moodle.
- `.env.moodle` исключён из Git, права файла — `600`. В шаблоне окружения пароли пустые.

Это результаты исходного этапа установки без LTI. Следующим этапом создан курс `RAG-LTI-LAB`, два тестовых студента и один LTI-элемент; реальные оценки 0/7/10 проверены для обоих. См. [результаты подключения](local-lti.md). Cloudflare и автоматический cron по-прежнему не подключались.

## Источники и обновление

- [Moodle 5.3: требования](https://moodledev.io/general/releases/5.3).
- [Официальные пакеты Moodle](https://download.moodle.org/releases/latest/).
- [PHP + Apache для Moodle, ARM64 и настройка DocumentRoot](https://github.com/moodlehq/moodle-php-apache).
- [Официальный moodle-docker для разработчиков](https://github.com/moodlehq/moodle-docker).
- [Настройка маршрутизатора и Apache](https://docs.moodle.org/503/en/Configuring_the_Router).

Наш Compose использует тот же PHP-образ, но ограничен двумя сервисами с постоянными томами. Полный upstream `moodle-docker` с Selenium/почтой не разворачивается.

Версия архива, SHA-256 и PHP image digest закреплены в `docker/moodle/Dockerfile`; PostgreSQL digest — в `compose.moodle.yaml`. Обновления выполняются осознанно: новая версия, новый checksum/digest, резервная копия томов и штатная процедура обновления Moodle, а не автоматическая пересборка `latest`.
